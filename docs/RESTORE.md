# Restore — bare-metal bootstrap for both dotfiles repos

This is the combined restore flow. Each repo's own README documents its piece;
this doc chains them and then lists what needs manual attention afterward.

## 1. General repo (chezmoi)

```bash
# install chezmoi (see chezmoi.io); then:
chezmoi init --apply DanielH2018/dotfiles
```

This deploys the general config.

## 2. Work repo (symlink farm) — work laptop only

```bash
git clone git@github.com:DanielH2018/work-laptop-config.git ~/work-laptop-config
~/work-laptop-config/install.sh
```

`install.sh` symlinks the work payload into `$HOME` and regenerates
`~/.claude/settings.json` on the next `chezmoi apply` (base + work overlay).

## 3. Verify everything landed

```bash
chezmoi diff     # expect empty — nothing pending against the source
chezmoi status   # expect nothing beyond expected per-machine drift
```

Unexpected output from either means something in step 1 or 2 did not deploy as declared —
re-run that step and inspect before moving on.

## 4. Manual checklist — per-machine content neither repo tracks

Secrets, caches, and other per-machine state are deliberately never declared as a chezmoi
target or a work-repo symlink, so nothing above restores them. That content is what you redo
by hand, and it is what this list is for.

- `~/.ssh/**` — no key survives a restore. Commit signing is enforced (`commit.gpgsign = true`),
  so **git refuses to commit until a signing key exists** — generate one before anything else:
  `ssh-keygen -t ed25519 -C <email> -f ~/.ssh/id_ed25519`, then add the `.pub` to GitHub under
  *SSH and GPG keys → Signing keys*. `dot_gitconfig.tmpl` probes that exact path for
  `user.signingkey` and `allowed_signers.tmpl` appends the pubkey, so a `chezmoi apply`
  afterwards wires both up with no source edit. On macOS 1Password supplies the key instead
  (see `~/.config/op/**` below) and this step does not apply.
- `~/.claude/settings.json` — **derived** from `settings.base.json` + `settings.work.json`;
  regenerated by `chezmoi apply`. Confirm it rendered (do not hand-edit).
- `~/.claude/projects/**` — per-machine Claude memory/history; nothing to restore.
- `~/.config/gh/hosts.yml` — re-auth: `gh auth login`.
- `~/.cache/**`, `~/.local/state/**` — runtime/cache; nothing to restore.
- `~/.config/op/**` — sign in to the 1Password CLI/app; Touch ID re-enrolls the SSH agent
  used for git commit signing and the `op://` shell references.
- `~/.config/chezmoi/**` — per-machine chezmoi config + persistent state, generated by
  `chezmoi init` from `home/.chezmoi.toml.tmpl` (answers the `work` and `profile` prompts).
  Re-run `chezmoi init` if the "config file template has changed" warning appears.

Desktop-environment state (KDE Plasma, GTK, Firefox, dconf) and generated payload (yazi's
`ya pkg install` plugins/flavors) are ignored too, but need nothing from you — the desktop
rewrites its own state on first login, and yazi reinstalls from the tracked `package.toml`.
