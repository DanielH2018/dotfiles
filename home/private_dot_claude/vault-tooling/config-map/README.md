# config-map

Deterministic generator for the **Claude Setup Map** — scans your Claude
Code config surface and emits one self-contained, collapsible HTML page at
`$CLAUDE_VAULT_DIR/Meta/Claude_Setup_Map.html`. Full design: [`SPEC.md`](SPEC.md).

Vault-optional: if `$CLAUDE_VAULT_DIR` is unset or its target is missing, the
project-layer section is skipped and no HTML is written — see
[`config_map/sources.py`](config_map/sources.py) and `generate.py`'s
`VAULT_PRESENT` check.

## What it does

Reads the deployed `~/.claude/` tree plus its two upstream sources
(`~/.local/share/chezmoi/home/private_dot_claude/` and
`~/work-laptop-config/.claude/`), the vault's own `.claude/` (if a vault is
configured and present), and a handful of local cache files, and renders:

- the settings precedence stack (managed → project-local → project → user)
- the `CLAUDE.md` `@`-include cascade
- hooks grouped by event
- skills / commands / agents / rules / output-styles inventory
- plugins grouped by marketplace
- MCP servers (local + needs-auth; connected connectors are best-effort only)
- scheduled (launchd) tasks

Every item is tagged with **provenance** — `chezmoi` (real file), `generated`
(templated chezmoi source), `work` (symlink into `work-laptop-config`),
`project` (this vault's own `.claude/`), or `unmanaged`.

## Run it

```sh
python3 ~/.claude/vault-tooling/config-map/generate.py
```

Prints a one-line status and exits 0 (including the "no vault" case). Also
wired to `/config-map`.

## How

- **Stdlib only.** No third-party runtime deps — see `pyproject.toml`.
- **No network, no LLM.** Pure filesystem scan; purpose text comes from
  frontmatter `description`, a leading `#` comment, or the filename — never
  generated by a model.
- **Deterministic.** Sorted iteration everywhere; same input → same output.
- **No secrets.** `~/.claude.json` is read only to pull `mcpServers` *keys*
  (see SPEC.md §8) — values are never touched, and the literal path never
  appears in a Bash command string, so `protect-secrets.sh` never fires.
- **Diff hygiene.** `generate.py` hashes the semantic payload (everything
  except the generated-at timestamp and source-repo SHAs) and only rewrites
  the HTML when that hash changes, so a no-op daily run doesn't churn git.
  The hash lives alongside this README in `.semantic_hash`.

## Layout

```
config-map/
  generate.py            # entrypoint
  config_map/
    sources.py            # path constants for the scan inputs
    scan.py                # filesystem walk + provenance detection
    model.py               # Item / Category / Layer / CascadeNode / SetupMap
    render.py              # HTML emit (inline CSS/JS)
  tests/                  # pytest — see pyproject.toml
  DAILY_WIRING.md          # options for the daily refresh (not yet wired)
```

## Tests

```sh
cd config-map
uv run --extra dev pytest -q   # uv resolves the dev extra in an ephemeral env; no venv to manage
```
