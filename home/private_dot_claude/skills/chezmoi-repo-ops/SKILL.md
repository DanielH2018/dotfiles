# chezmoi-repo-ops

A change here crosses four hops: source commit → `origin/main` → the primary checkout's
working tree → `$HOME`. `bin/land` moves the second. Nothing moves the third for you, and
`chezmoi apply` moves the fourth from whatever the third currently holds. In the two worst
cases `chezmoi diff` reports nothing wrong, so a clean diff is not proof.

Who is allowed to run `land` and `try` — and why you run them rather than print them — is in
the repo's `CLAUDE.md`. This is what to do afterwards.

## After `bin/land`: sync, then deploy

`land` merges by pushing `<branch>:main`, which updates **origin/main only**. The primary
checkout's local `main` stays at the pre-merge commit, and chezmoi reads its source from that
checkout's working tree — so an apply now redeploys pre-merge content and silently reverts what
just landed. `chezmoi diff` is quiet, because deployed and (stale) source genuinely match.

Check what the primary checkout is on first; the two cases differ:

```sh
git -C ~/.local/share/chezmoi rev-parse --abbrev-ref HEAD
```

- **On `main`** — `git fetch origin main && git merge --ff-only origin/main`. Verify with
  `git show HEAD:<source path>`.
- **On another branch** (a session parked one there) — the merge above would pull origin/main
  *into that in-flight branch*. Use `git fetch origin main:main`, which fast-forwards the
  non-checked-out ref and fails loudly instead of clobbering. Verify with
  `git show main:<source path>`.

Syncing the ref still isn't deploying. While the checkout sits on a pre-merge branch, every
apply deploys pre-merge content and it looks like the change never landed. `bin/try --back`
(checkout main + apply) is the fix; run `git diff --stat <parked-branch> main -- home/` first
to see what the switch un-deploys.

**The tell that the fast-forward didn't happen:** `land` finishes with `worktree still holds
<branch>; from the primary: git worktree remove <path>` and `git worktree list` shows only the
primary. That is a branch created in the primary checkout rather than a worktree — `git
checkout main`, then take the *on main* case above.

Done when the primary checkout is on `main`, `git show main:<path>` holds the landed content,
and the file in `$HOME` matches it.

A config already read by a running process needs a separate nudge; the deployed file only
reaches *future* shells and servers. For tmux: `tmux -S /tmp/tmux-1000/default set -g <option>`.

## The mirror case: `chezmoi apply --source <worktree>`

Deploying straight from a worktree is the only way to test unlanded config, and it leaves
`$HOME` *ahead* of what the primary checkout can reproduce — so the next plain apply reverts it.
Unlike the stale-source case, `chezmoi diff <path>` against the default source **does** show the
discrepancy, and it is the cheapest proof of what is still unlanded. Run it after any
worktree-source apply.

`~/.claude/settings.json` is generated by a `modify_` script that refuses a dirty tree;
`CLAUDE_SETTINGS_ALLOW_DIRTY=1` renders it for inspection before you commit.

## When the pre-push gate fails

Never take the gate's own `git push --no-verify` suggestion — it bypasses the signing gate too.

- **`FileNotFoundError: [Errno 2] ... 'node'`** under `✗ unit tests (node --test)` is a missing
  interpreter, not a broken suite. Node is installed via **fnm**
  (`~/.local/share/fnm/aliases/default/bin`; there is no `~/.nvm`), and a background job's shell
  starts without it on PATH. Prefix the invocation in the *same* Bash call — an `export` in a
  prior call does not survive, only cwd persists:

  ```sh
  PATH="$HOME/.local/share/fnm/aliases/default/bin:$PATH" ./bin/land
  ```

- **config-soak exits non-zero** — the change touched tracked config (`settings.base.json`,
  hooks, agents, skills, `CLAUDE.md`) and needs acknowledging:
  `cd <repo-or-worktree> && node bin/config-soak land`, then commit the updated
  `config-soak.json`. The ledger is anchored to the script's own location, so a worktree must run
  its own copy; that compound form is the shape `allow-compound-bash.sh` auto-approves.

## Touching an extensionless script

prek types a file as shell by **extension**, or by **shebang — only if the file is executable**.
So an extensionless script needs the `+x` bit *in git* to be linted, and chezmoi's `executable_`
prefix sets the **deployed** mode, not the source mode. A `100644` source deploys as 0755 and
nothing looks broken while it goes unlinted.

Run `shellcheck <file>` directly and **check the exit code**. Do not count findings by grepping
for the `^--^ SC` caret shape — it misses SC1072/SC1073, which emit a single caret, and a pattern
written `-- SC[0-9]+` silently parses as a flag and undercounts. Two related traps: any comment
line starting with the word "shellcheck" parses as a directive, and a `disable=` directive placed
before the first command is file-wide, not scoped.

The zsh completions `sandbox/_claude-sandbox` and `_cts` cannot be covered — ShellCheck supports
sh/bash/dash/ksh only and errors SC1071 on zsh.

## Concurrent sessions

Other sessions move this repo constantly, so re-read `git rev-parse HEAD` rather than trusting a
value read a moment earlier. Never `git stash` or reset: the index is shared across worktrees,
not per-worktree. The repo's `CLAUDE.md` carries the rest.
